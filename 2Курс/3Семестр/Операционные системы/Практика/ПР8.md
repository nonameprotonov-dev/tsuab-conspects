## Теоретическая часть

**Управление памятью** — задача операционной системы, которая управляет иерархией памяти (кэш, RAM, диск) и предоставляет процессам удобную абстракцию — виртуальную память. Менеджер памяти следит за тем, какие части памяти используются, выделяет память процессам и освобождает её при завершении.

### Виртуальная память

ОС «обманывает» каждый процесс, заставляя его думать, что:

- у него есть огромное непрерывное адресное пространство (например, 0–4 ГБ на 32-битной системе);
- он единственный пользователь памяти;
- он может свободно читать и писать в любую часть этого пространства.

На самом деле физическая RAM ограничена, разделена между сотнями процессов, и процесс не имеет прямого доступа к ней. ОС отображает виртуальные страницы на физические через **таблицу страниц (page table)**.

**Зачем нужна виртуальная память:**

| Цель | Как достигается |
|---|---|
| Изоляция | Процесс A не может читать память процесса B |
| Защита | Запись в read-only страницу вызывает исключение |
| Эффективность | Не нужно загружать всю программу в RAM — только нужные части |
| Удобство | Программист работает с линейными адресами, не думая о физике |

### Страничная организация

Память делится на фиксированные блоки — **страницы** (обычно 4 КБ). Виртуальное адресное пространство процесса тоже делится на страницы того же размера. ОС поддерживает таблицу страниц — отображение виртуальных страниц на физические.

Адрес вычисляется как: `Адрес = (номер страницы × размер страницы) + смещение`.

**Преимущества страниц:** фиксированный размер упрощает управление, не нужно компактировать память (в отличие от сегментов), легко выгружать неиспользуемые страницы на диск (swap).

### Page Fault (ошибка страницы)

**Page fault** — исключение, генерируемое MMU (Memory Management Unit), когда процесс обращается к виртуальному адресу, который не отображён в физическую память, или нарушает права доступа.

**Как обрабатывается page fault:**

1. Процессор передаёт управление обработчику page fault в ядре ОС.
2. Ядро проверяет: допустим ли адрес? есть ли права?
3. Если всё в порядке:
   - выделяет новую физическую страницу;
   - инициализирует её (нулями или данными с диска);
   - обновляет таблицу страниц;
   - возобновляет выполнение процесса.

Процесс ничего не замечает — это нормальный механизм работы виртуальной памяти.

### Таблица страниц (Page Table)

На x86_64 таблица страниц иерархическая (4 уровня). Каждый уровень — таблица по 512 записей. Это экономит память: если регион не используется, его подтаблицы не создаются.

**Запись в таблице страниц (PTE) содержит:**

- адрес физической страницы;
- биты прав доступа: Read/Write, User/Supervisor;
- бит `Present` — загружена ли страница в RAM;
- бит `Dirty` — была ли запись в страницу (важно для swap);
- бит `Accessed` — использовалась ли страница.

### Swap (подкачка)

Когда RAM заполнена, ОС выгружает редко используемые страницы на диск:

- **Windows:** `pagefile.sys`
- **Linux:** swap-раздел или файл

**Как работает:**

1. При нехватке RAM ОС выбирает жертву (например, по алгоритму LRU).
2. Если страница грязная — сохраняет её на диск.
3. Освобождает физическую страницу.
4. При новом обращении — page fault, загрузка со swap.

Частый swap — это **thrashing** (система тратит больше времени на подкачку, чем на работу).

## Сравнение Windows и Linux

| Характеристика | Windows | Linux |
|---|---|---|
| Размер страницы | 4 КБ (по умолчанию) | 4 КБ (x86_64) |
| Таблица страниц | Иерархическая (4 уровня в x64) | 4-уровневая (PGD → PUD → PMD → PTE) |
| Page Fault Handler | `MmAccessFault` | `do_page_fault` |
| Swap | `pagefile.sys` | swap-раздел/файл |
| API для работы с памятью | `VirtualAlloc`, `VirtualFree` | `mmap`, `brk`, `sbrk` |

## Практические наблюдения

### Наблюдение в Linux: `/proc/<pid>/maps`

Файл `/proc/<pid>/maps` показывает виртуальные диапазоны процесса.

```bash
cat /proc/self/maps
```

Пример строки:

```
55d8a9b00000-55d8a9b02000 rw-p 00000000 00:00 0
```

- `rw-p` — права: read, write, private.
- Диапазон: 0x55d8a9b00000 – 0x55d8a9b02000 (8 КБ).
- `00:00` — не привязан к файлу (анонимная память).

### Наблюдение в Windows: VMMap

**VMMap** (Sysinternals) показывает:

- **Private Bytes** — память, уникальная для процесса;
- **Working Set** — память, загруженная в RAM;
- **Page Table** — использование таблиц страниц.

**Пошаговая инструкция:**

1. Скачать и запустить VMMap с сайта Microsoft.
2. Выбрать процесс для анализа.
3. В сводке (Summary) посмотреть `Committed`, `Private`, `Mapped`.
4. На диаграмме типы памяти разделены цветами: жёлтый — Private Data, фиолетовый — Image (EXE/DLL), голубой — Mapped File.
5. Для поиска утечек смотреть на `Committed` — объём виртуальной памяти, для которой выделено место в ОЗУ или файле подкачки.
6. Включить отображение свободных областей (Options → Show Free Regions), чтобы оценить фрагментацию.

Область с типом **Private Data** — это выделенная процессом память.

## Примеры кода

### Выделение памяти в Windows (C)

```c
// win_memory.c
#include <windows.h>
#include <stdio.h>

int main() {
    // Выделить 64 КБ виртуальной памяти
    LPVOID mem = VirtualAlloc(
        NULL,                       // Адрес (NULL = ОС выбирает)
        65536,                      // Размер (64 КБ)
        MEM_COMMIT | MEM_RESERVE,   // Зарезервировать + выделить
        PAGE_READWRITE              // Права доступа
    );

    if (mem == NULL) {
        printf("VirtualAlloc failed (%d)\n", GetLastError());
        return 1;
    }

    printf("Память выделена по адресу: %p\n", mem);

    char* ptr = (char*)mem;
    ptr[0] = 'A';
    ptr[65535] = 'Z';

    VirtualFree(mem, 0, MEM_RELEASE);
    return 0;
}
```

**Объяснение:**

- `VirtualAlloc` работает с виртуальным адресным пространством процесса.
- `MEM_RESERVE` — резервирует адреса, но не использует RAM.
- `MEM_COMMIT` — выделяет физическую память (при первом обращении → page fault).

### Выделение памяти в Linux (C)

```c
// linux_memory.c
#define _GNU_SOURCE
#include <sys/mman.h>
#include <stdio.h>
#include <unistd.h>

int main() {
    size_t size = 65536; // 64 КБ

    void* mem = mmap(
        NULL,
        size,
        PROT_READ | PROT_WRITE,
        MAP_PRIVATE | MAP_ANONYMOUS,
        -1, 0
    );

    if (mem == MAP_FAILED) {
        perror("mmap failed");
        return 1;
    }

    printf("Память выделена по адресу: %p\n", mem);

    char* ptr = (char*)mem;
    ptr[0] = 'A';
    ptr[65535] = 'Z';

    munmap(mem, size);
    return 0;
}
```

**Объяснение:**

- `mmap` — универсальный системный вызов для отображения памяти.
- `MAP_ANONYMOUS` — память не связана с файлом (как `malloc`).
- При первом обращении — page fault, ядро выделяет физическую страницу.

## Эксперимент «ленивая» аллокация

```c
// lazy.c
#include <stdio.h>
#include <stdlib.h>

int main() {
    size_t size = 1024 * 1024 * 1024; // 1 ГБ
    char* big = (char*)malloc(size);

    printf("Выделено 1 ГБ. Нажмите Enter...\n");
    getchar(); // RAM ещё не используется!

    // Теперь запишем:
    for (size_t i = 0; i < size; i += 4096) {
        big[i] = 1; // триггер page fault каждые 4 КБ
    }

    printf("Теперь RAM использована.\n");
    free(big);
    return 0;
}
```

**Наблюдение:**
linux:
- **До записи:** RAM почти не растёт (только виртуальные адреса).
	![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20261005112947.png]]
- **После записи:** RAM резко увеличивается (page fault → выделение физической памяти).
	![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20261005113323.png]]
win:
- Вся память используется с самого старта
	![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20261005111817.png]]
Это демонстрирует **ленивую (on-demand) аллокацию** только в Linux.

## Мини-задача: измерение памяти до и после записи

```c
// memory_test.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void print_mem_usage() {
    FILE* f = fopen("/proc/self/status", "r");
    char line[256];
    while (fgets(line, sizeof(line), f)) {
        if (strncmp(line, "VmRSS:", 6) == 0) {
            printf("RAM: %s", line);
            break;
        }
    }
    fclose(f);
}

int main() {
    size_t size = 100 * 1024 * 1024; // 100 МБ
    char* mem = (char*)malloc(size);

    printf("После malloc:\n");
    print_mem_usage();

    printf("Нажмите Enter для записи...\n");
    getchar();

    memset(mem, 1, size); // запись во всю память

    printf("После записи:\n");
    print_mem_usage();

    free(mem);
    return 0;
}
```

![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20261005113541.png]]

**Интерпретация:**

- `malloc` только резервирует виртуальные адреса.
- Физическая память выделяется при первом обращении (page fault).
- Поэтому `VmRSS` (резидентная память) растёт только после `memset`.

## Управление памятью в C и Python

### Управление памятью в C (ручное)

В C программист сам решает, когда выделить память и когда её освободить.

**Основные области памяти:**

- **Стек (Stack):** автоматическое управление, локальные переменные, освобождается при выходе из области видимости. Быстро, но размер известен на этапе компиляции.
- **Куча (Heap):** ручное управление, данные, размер которых неизвестен заранее или которые должны жить дольше функции. Управляется через указатели.

**Ключевые функции `<stdlib.h>`:**

| Функция | Назначение |
|---|---|
| `malloc(size)` | Выделить блок памяти (не инициализирует) |
| `calloc(n, size)` | Выделить память под n элементов, инициализирует нулями |
| `realloc(ptr, new_size)` | Изменить размер уже выделенного блока |
| `free(ptr)` | Освободить память |

**Типичные ошибки в C:**

- **Утечка памяти (Memory Leak):** выделили `malloc`, но забыли `free`.
- **Dangling Pointer:** освободили память, но продолжаете использовать указатель.
- **Double Free:** попытка освободить одну и ту же память дважды.
- **Buffer Overflow:** запись данных за пределы выделенного блока.

### Управление памятью в Python (автоматическое)

В Python программист редко думает о памяти напрямую — этим занимается интерпретатор.

**Механизмы:**

- **Счётчик ссылок (Reference Counting):** у каждого объекта есть счётчик, сколько переменных на него ссылается. Когда счётчик становится 0, память освобождается мгновенно.
- **Сборщик мусора (Garbage Collector, GC):** нужен для обработки циклических ссылок. Счётчик ссылок в этом случае не сработает.
- **Менеджер памяти Python:** выделяет большие блоки у ОС, а внутри управляет мелкими объектами.

**Особенности:**

- Всё есть объект (даже числа и функции).
- Переменные — это просто ярлыки (ссылки) на объекты.
- Изменяемые (`list`, `dict`) и неизменяемые (`int`, `str`, `tuple`) типы ведут себя по-разному при присваивании.

## Практическая работа на C и Python

### Задание 1: C (динамический массив)

**Цель:** научиться выделять, изменять размер и освобождать память в куче.

**Задача:** написать программу, которая:

1. Спрашивает у пользователя количество чисел N.
2. Выделяет память под массив из N целых чисел.
3. Заполняет массив числами от пользователя.
4. Выводит среднее арифметическое.
5. Обязательно освобождает память.

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int n;
    printf("Введите количество элементов: ");
    if (scanf("%d", &n) != 1 || n <= 0) {
        printf("Ошибка ввода!\n");
        return 1;
    }

    // 1. ВЫДЕЛЕНИЕ ПАМЯТИ
    int *arr = (int*)malloc(n * sizeof(int));

    if (arr == NULL) {
        printf("Не удалось выделить память!\n");
        return 1;
    }

    printf("Введите %d чисел:\n", n);
    long long sum = 0;

    for (int i = 0; i < n; i++) {
        scanf("%d", &arr[i]);
        sum += arr[i];
    }

    printf("Среднее арифметическое: %.2f\n", (double)sum / n);

    // 2. ОСВОБОЖДЕНИЕ ПАМЯТИ
    free(arr);
    arr = NULL;

    return 0;
}
```

**Дополнительное задание:** выделить память сначала для 5 элементов, в цикле вводить числа, при нехватке места использовать `realloc` для увеличения массива в 2 раза, в конце освободить память.

### Задание 2: Python (анализ памяти и GC)

**Цель:** понять, как работают ссылки, счётчик ссылок и увидеть работу сборщика мусора.

#### Упражнение 2.1: счётчик ссылок и id

```python
import sys
import gc

# 1. Создание объекта
a = [1, 2, 3]
print(f"ID объекта a: {id(a)}")
print(f"Размер объекта a (байт): {sys.getsizeof(a)}")

# 2. Создание ссылки
b = a
print(f"ID объекта b: {id(b)}")  # ID будет таким же!

# 3. Проверка счётчика ссылок
print(f"Счётчик ссылок на a: {sys.getrefcount(a)}")

# 4. Удаление ссылки
del b
print(f"Счётчик ссылок после del b: {sys.getrefcount(a)}")

# 5. Изменяемость
a.append(4)
# b уже удалён, но объект a изменился
print(f"Содержимое a после append: {a}")
```

#### Упражнение 2.2: циклические ссылки и сборщик мусора

```python
import gc
import tracemalloc

tracemalloc.start()

class Node:
    def __init__(self, value):
        self.value = value
        self.ref = None

# 1. Создаём циклическую ссылку
node1 = Node(1)
node2 = Node(2)

node1.ref = node2
node2.ref = node1  # Цикл: 1 -> 2 -> 1

# Удаляем внешние ссылки
del node1
del node2

# 2. Принудительный запуск сборщика мусора
collected = gc.collect()
print(f"Объектов удалено сборщиком мусора: {collected}")

# 3. Проверка потребления памяти
current, peak = tracemalloc.get_traced_memory()
print(f"Текущее использование: {current / 1024 / 1024:.2f} MB")
print(f"Пиковое использование: {peak / 1024 / 1024:.2f} MB")

tracemalloc.stop()
```

**Дополнительное задание:** создать список из 1 миллиона целых чисел, замерить память через `tracemalloc`, затем список из 1 миллиона строк `"hello world"`, замерить память. Объяснить разницу (интернирование строк и размер объекта).

## Сравнительный анализ C и Python

| Характеристика | C | Python |
|---|---|---|
| Контроль | Полный (байт в байт) | Ограниченный (объекты) |
| Безопасность | Низкая (легко уронить систему) | Высокая (изоляция) |
| Скорость работы | Очень высокая (нет накладных расходов) | Ниже (работа GC, проверка типов) |
| Утечки памяти | Частая проблема программиста | Редко (но возможны, если держать ссылки) |
| Где используется | ОС, драйверы, встраиваемые системы, игры | Web, Data Science, скрипты, автоматизация |

**Инструменты для отладки памяти:**

- **Для C:** Valgrind (`valgrind --leak-check=full ./my_program`), AddressSanitizer (`-fsanitize=address`).
- **Для Python:** `memory_profiler` (`pip install memory-profiler`), `objgraph` (визуализация связей между объектами).
