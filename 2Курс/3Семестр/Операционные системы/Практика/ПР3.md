"Проверка концепций ОС с помощью PowerShell"
## 1. Двойной режим (User Mode / Kernel Mode)

### Теоретическая часть.
В Windows код выполняется в одном из двух режимов: пользовательском (user mode) или ядра (kernel mode). Приложения работают в user mode и не имеют прямого доступа к оборудованию. Для выполнения привилегированных операций они вызывают системные вызовы (syscalls), при которых процессор переключается в kernel mode. В PowerShell время, проведённое процессом в каждом из режимов, можно увидеть через свойства `UserProcessorTime` и `PrivilegedProcessorTime`.

### Ожидаемый результат.
Таблица, в которой для процессов показано время в пользовательском режиме (`UserProcessorTime`) и в режиме ядра (`PrivilegedProcessorTime`). Например, системные процессы (`System`, `Idle`) имеют больше времени в kernel mode, а пользовательские приложения — в user mode.

### Результат.
**Команды PowerShell:**
```powershell
Get-Process | Sort-Object CPU -Descending |
    Select-Object -First 10 Name, Id, CPU, UserProcessorTime, PrivilegedProcessorTime | Out-Host -Paging
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917155417.png]]

**Для текущего процесса:**
```powershell
$p = Get-Process -Id $PID
$p | Select-Object Name, Id, UserProcessorTime, PrivilegedProcessorTime, CPU
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917155528.png]]

### Промежуточный вывод.  
Концепция двойного режима подтверждена: PowerShell позволяет раздельно наблюдать пользовательское и привилегированное процессорное время.

## 2. Абстракция (Abstraction)

### Теоретическая часть.  
Операционная система скрывает физические устройства и ресурсы за логическими объектами. В Windows это дескрипторы (`HANDLE`), которые абстрагируют файлы, каналы, события, устройства. PowerShell также работает с объектами .NET, а не с «сырыми» байтами, что является примером абстракции.

### Ожидаемый результат.
`HandleCount` показывает количество дескрипторов, открытых процессом. Команда `Get-ChildItem` возвращает объекты `FileInfo` со свойствами `Name`, `Length`, `Attributes`, а не просто строки. Это демонстрирует, что ОС и PowerShell предоставляют абстракцию над физическими файлами и устройствами.
### Результат.
**Команды PowerShell:**
```powershell
Get-Process | Sort-Object HandleCount -Descending |
    Select-Object -First 10 Name, Id, HandleCount
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917160444.png]]
**Абстракция файловой системы:**
```powershell
Get-ChildItem C:\Windows\System32 -File |
    Select-Object -First 5 Name, Length, Attributes
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917160551.png]]

**Просмотр членов объекта:**
```powershell
Get-ChildItem C:\Windows\System32\notepad.exe | Get-Member | Out-Host -Paging
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917160725.png]]
### Промежуточный вывод.
Концепция абстракции подтверждена: доступ к ресурсам осуществляется через логические объекты и дескрипторы.

## 3. Виртуализация (Virtualization)

### Теоретическая часть.
Виртуализация памяти — одна из ключевых концепций ОС. Каждый процесс получает собственное виртуальное адресное пространство, изолированное от других процессов. Физическая память распределяется операционной системой между процессами по мере необходимости. Процесс «думает», что работает с непрерывным участком памяти, тогда как на самом деле страницы могут быть разбросаны по физической памяти или выгружены в файл подкачки. В PowerShell объём виртуальной памяти процесса можно увидеть через свойства `VM`, `WS`, `PM`, `NPM`.

### Ожидаемый результат.
У каждого процесса большой размер виртуальной памяти (`VM`), часто превышающий доступную физическую память. Это подтверждает, что процессы работают в собственных виртуальных адресных пространствах. Свойство `WorkingSet` (`WS`) показывает объём физической памяти, реально используемой процессом, а `PrivateMemory` (`PM`) — объём приватной памяти. Команда `Get-CimInstance Win32_OperatingSystem` покажет общие параметры виртуальной памяти системы.

### Результат.
**Виртуальная память процессов:**
```powershell
Get-Process | Sort-Object VM -Descending |
    Select-Object -First 10 Name, Id, VM, WS, PM, NPM
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917161420.png]]

**Виртуальная память текущего процесса:**
```powershell
$p = Get-Process -Id $PID
[PSCustomObject]@{
    Name          = $p.Name
    Id            = $p.Id
    VirtualMemory = $p.VM
    WorkingSet    = $p.WS
    PrivateMemory = $p.PM
    PagedMemory   = $p.NPM
}
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917161508.png]]

**Общая информация о памяти системы:**
```powershell
Get-CimInstance Win32_OperatingSystem |
    Select-Object TotalVirtualMemorySize, TotalVisibleMemorySize, FreeVirtualMemory
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917161537.png]]
### Промежуточный вывод.
Концепция виртуализации памяти подтверждена: PowerShell показывает, что каждый процесс работает в собственном виртуальном адресном пространстве, а размер виртуальной памяти процессов может превышать объём физической памяти системы. Это возможно именно благодаря механизму виртуальной памяти.

## 4. Мультиплексирование (Multiplexing)

### Теоретическая часть.
Мультиплексирование в ОС — это разделение ресурсов между множеством потребителей. Планировщик потоков (Thread Scheduler) делит процессорное время между потоками разных процессов, создавая иллюзию одновременной работы. Каждый поток получает квант времени (time slice), после чего планировщик переключает контекст на другой поток. В PowerShell можно посмотреть количество потоков у процессов и распределение загрузки CPU между ними.

### Ожидаемый результат.
У большинства процессов несколько потоков. Планировщик Windows распределяет между ними кванты времени. Команды покажут, что один физический CPU делится между множеством потоков и процессов. Команда `Get-CimInstance Win32_PerfFormattedData_PerfProc_Process` покажет, какие процессы потребляют CPU в данный момент.

### Результат.
**Количество потоков у процессов:**
```powershell
Get-Process |
    Select-Object Name, Id,
        @{Name='Threads';Expression={$_.Threads.Count}}, CPU |
    Sort-Object Threads -Descending |
    Select-Object -First 15
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917165352.png]]

**Детальная информация по потокам через CIM:**
```powershell
Get-CimInstance Win32_Thread |
    Group-Object ProcessHandle |
    Sort-Object Count -Descending |
    Select-Object -First 10 @{Name='ProcessHandle';Expression={$_.Name}}, Count
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917165442.png]]

**Распределение загрузки CPU по процессам:**
```powershell
Get-CimInstance Win32_PerfFormattedData_PerfProc_Process |
    Where-Object { $_.Name -ne '_Total' -and $_.Name -ne 'Idle' } |
    Sort-Object PercentProcessorTime -Descending |
    Select-Object -First 10 Name, IDProcess, PercentProcessorTime
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917165520.png]]

### Промежуточный вывод.
Концепция мультиплексирования подтверждена: один CPU делится между множеством потоков и процессов. Планировщик Windows распределяет процессорное время, а PowerShell позволяет наблюдать количество потоков и текущую загрузку CPU каждым процессом.

## 5. Изоляция и защита (Isolation and Protection)

### Теоретическая часть.
Изоляция процессов предотвращает их взаимное влияние и несанкционированный доступ к ресурсам. В Windows используются уровни целостности (integrity levels), сессии, списки управления доступом (ACL) и механизм AppContainer. Например, браузеры в Protected Mode работают с низким уровнем целостности, а системные службы — в отдельной сессии 0, изолированной от пользовательских приложений. В PowerShell это можно проверить через `whoami /groups`, `Get-Acl`, `SessionId`.

### Ожидаемый результат.
`whoami /groups` покажет `Mandatory Label\Medium Mandatory Level` (или `High` для процессов, запущенных от администратора). `Group-Object SessionId` покажет, что службы работают в сессии 0, а пользовательские приложения — в сессии 1 и выше. `Get-Acl` продемонстрирует разграничение прав доступа к системным файлам между пользователями и системой.

### Результат.
**Уровень целостности текущего процесса:**
```powershell
whoami /groups | findstr "Mandatory Label"
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917165623.png]]

**Изоляция сессий:**
```powershell
Get-Process | Select-Object Name, Id, SessionId | Group-Object SessionId
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917165654.png]]

**Права доступа к системному файлу (ACL):**
```powershell
Get-Acl C:\Windows\System32\notepad.exe | Format-List
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917165742.png]]

**Процессы браузеров (пример изоляции):**
```powershell
Get-Process | Where-Object { $_.Name -match 'msedge|iexplore|chrome' } |
    Select-Object Name, Id, Path
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917165809.png]]
### Промежуточный вывод.
Концепция изоляции и защиты подтверждена: процессы разделены по сессиям, уровням целостности и правам доступа. Системные службы изолированы в сессии 0, пользовательские приложения — в сессии 1, а разграничение прав через ACL предотвращает несанкционированный доступ к системным файлам.
