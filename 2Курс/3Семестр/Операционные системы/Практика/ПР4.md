"Проверка концепций ОС с помощью WSL2"
## 1. Двойной режим (User Mode / Kernel Mode)

### Теоретическая часть.
WSL2, в отличие от WSL1, использует настоящее ядро Linux, работающее в легковесной виртуальной машине на базе Hyper-V. Это означает, что системные вызовы (syscalls) из пользовательского пространства Linux обрабатываются реальным ядром Linux, которое работает в привилегированном режиме (Ring 0) внутри виртуальной машины. Переключение между режимами ядра и пользователя происходит внутри Linux, а не транслируется в Windows API. В PowerShell можно увидеть, что WSL2 — это отдельный процесс, а внутри WSL2 с помощью `strace` можно наблюдать системные вызовы.

### Ожидаемый результат.
Команда `uname -r` внутри WSL2 покажет версию ядра Linux (например, `5.15.90.1-microsoft-standard-WSL2`). Команда `strace` продемонстрирует, как пользовательская программа выполняет системные вызовы, которые обрабатываются ядром. В PowerShell команда `Get-Process -Name "wsl"` покажет процесс, связанный с виртуальной машиной WSL2.

### Результат.
**Проверка версии ядра Linux в WSL2:**
```bash
uname -r
uname -a
```

Концепция двойного режима подтверждена: WSL2 использует реальное ядро Linux, работающее в привилегированном режиме внутри виртуальной машины. Системные вызовы из пользовательского пространства обрабатываются ядром, что можно наблюдать с помощью `strace`.

## 2. Абстракция (Abstraction)

### Теоретическая часть.
WSL2 предоставляет мощный слой абстракции. С одной стороны, он скрывает от пользователя сложность виртуализации и работы с реальным ядром. С другой стороны, он абстрагирует доступ к файловой системе Windows через точки монтирования `/mnt/c`, `/mnt/d`. Это позволяет Linux-приложениям работать с файлами Windows как с обычными файлами в Linux-системе. В PowerShell абстракция проявляется в том, что WSL2 управляется через единый интерфейс командной строки.

### Ожидаемый результат.
Внутри WSL2 команда `ls /mnt/c` покажет содержимое диска C: Windows. Команда `mount | grep mnt` покажет точки монтирования. Команда `df -h` отобразит файловые системы, доступные в WSL2. В PowerShell команда `wsl -l -v` покажет список дистрибутивов, абстрагируя их как отдельные среды.

### Результат.
**Доступ к файловой системе Windows через /mnt:**
```bash
ls /mnt/c
mount | grep mnt
df -h
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917170733.png]]

**Список дистрибутивов WSL из PowerShell:**
```powershell
wsl -l -v
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917170758.png]]

### Промежуточный вывод.
Концепция абстракции подтверждена: WSL2 абстрагирует доступ к файловой системе Windows через точки монтирования, а PowerShell предоставляет единый интерфейс для управления дистрибутивами.

## 3. Виртуализация (Virtualization)

### Теоретическая часть.
WSL2 основан на легковесной виртуальной машине (lightweight utility VM), которая использует технологии Hyper-V для запуска реального ядра Linux. Это обеспечивает полную совместимость с системными вызовами Linux и высокую производительность, близкую к нативной. Виртуализация в WSL2 включает виртуализацию процессора, памяти и устройств. В PowerShell можно наблюдать процессы, связанные с виртуальной машиной WSL2.

### Ожидаемый результат.
В PowerShell команда `Get-Process vmmem` покажет процесс, представляющий виртуальную машину WSL2, который потребляет память и CPU. Команда `Get-Service LxssManager` покажет службу, управляющую WSL. Внутри WSL2 команда `free -h` покажет объём виртуальной памяти, `lscpu` — характеристики виртуального процессора, `systemd-detect-virt` определит тип виртуализации (например, `microsoft` или `wsl`).

### Результат.
**Процессы и службы WSL в PowerShell:**
```powershell
Get-Process -Name "vmmem", "wsl", "wslservice" -ErrorAction SilentlyContinue |
    Select-Object Name, Id, CPU, WS, PM
```

**Информация о виртуальном оборудовании внутри WSL2:**
```bash
free -h
lscpu
systemd-detect-virt
```

### Промежуточный вывод.
Концепция виртуализации подтверждена: WSL2 запускает полноценное ядро Linux в легковесной виртуальной машине. PowerShell показывает процессы виртуальной машины, а внутри WSL2 видны виртуальные ресурсы (память, CPU).

## 4. Мультиплексирование (Multiplexing)

### Теоретическая часть.
Внутри виртуальной машины WSL2 работает полноценный планировщик Linux (CFS — Completely Fair Scheduler). Он распределяет процессорное время между запущенными процессами и потоками. С точки зрения Windows, вся виртуальная машина WSL2 представляет собой один или несколько процессов, которые, в свою очередь, планируются планировщиком Windows на хосте. В PowerShell можно наблюдать нагрузку на CPU от процессов WSL, а внутри WSL2 — распределение CPU между процессами.

### Ожидаемый результат.
Внутри WSL2 команда `top` или `htop` покажет распределение CPU между процессами. Команда `ps -eLf` отобразит потоки. В PowerShell команда `Get-Process vmmem` покажет общую загрузку CPU виртуальной машиной WSL2.

### Результат.
**Распределение CPU внутри WSL2:**
```bash
top -b -n 1 | head -20
ps -eLf | head -20
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917175641.png]]

**Загрузка CPU процессом vmmemwsl в PowerShell:**
```powershell
Get-Process -Name "vmmemwsl" | Select-Object Name, Id, CPU, WS
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917175753.png]]

### Промежуточный вывод.
Концепция мультиплексирования подтверждена: внутри WSL2 планировщик Linux распределяет процессорное время между процессами и потоками, а с точки зрения Windows вся виртуальная машина WSL2 представляет собой один процесс, который планируется планировщиком Windows.

## 5. Изоляция и защита (Isolation and Protection)

### Теоретическая часть.
WSL2 использует механизм пространств имен (namespaces) Linux для изоляции. Каждый дистрибутив WSL2 работает в своем собственном наборе пространств имен (PID, mount, network и т. д.). Это означает, что процессы в одном дистрибутиве не видят процессы в другом, и каждый дистрибутив имеет свою файловую систему. Это очень похоже на технологию контейнеров, например, Docker. В PowerShell можно управлять изоляцией, запуская и останавливая отдельные дистрибутивы.

### Ожидаемый результат.
Если запустить два разных дистрибутива WSL2, то команда `ps aux` в одном дистрибутиве не покажет процессы из другого. Команда `mount` в каждом дистрибутиве покажет свою файловую систему. В PowerShell команда `wsl -l -v` покажет список дистрибутивов, каждый из которых изолирован.

### Результат.
**Список дистрибутивов и их состояние:**
```powershell
wsl -l -v
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917175839.png]]

**Проверка изоляции процессов между дистрибутивами:**
```bash
# В первом дистрибутиве (например, Ubuntu-24.04)
ps aux | head -10
# Во втором дистрибутиве (например, Ubuntu-22.04)
ps aux | head -10
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917175928.png]]

**Проверка изоляции файловых систем:**
```bash
mount | grep -E "^/dev" | head -10
```
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260917175947.png]]

### Промежуточный вывод.
Концепция изоляции подтверждена: каждый дистрибутив WSL2 изолирован с помощью пространств имен Linux. Процессы и файловые системы одного дистрибутива не видны в другом, что обеспечивает безопасность и независимость сред.

## Итоговый вывод по работе №4

В ходе практической работы с помощью WSL2 и PowerShell были обнаружены и подтверждены все пять ключевых концепций операционных систем:

1. **Двойной режим** — через реальное ядро Linux в WSL2 и системные вызовы, наблюдаемые с помощью `strace`.
2. **Абстракция** — через точки монтирования `/mnt/c` и единый интерфейс управления дистрибутивами из PowerShell.
3. **Виртуализация** — через легковесную виртуальную машину Hyper-V, процессы `vmmem` и `wslservice`, а также виртуальные ресурсы внутри WSL2.
4. **Мультиплексирование** — через планировщик Linux внутри WSL2 и планирование процесса виртуальной машины в Windows.
5. **Изоляция** — через пространства имен Linux, обеспечивающие независимость дистрибутивов WSL2.

WSL2 является мощным инструментом для практического изучения концепций операционных систем, так как объединяет в себе реальное ядро Linux, виртуализацию и изоляцию на уровне контейнеров. Полученные результаты соответствуют теоретическим сведениям о принципах работы современных операционных систем.
