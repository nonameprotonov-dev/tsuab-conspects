## Исследование структуры файловой системы

### Linux (WSL2)

```bash
# 1. Просмотр корневой директории
ls -la /

# 2. Назначение основных директорий:
# /bin   - основные исполняемые файлы
# /etc   - конфигурационные файлы
# /home  - домашние директории пользователей
# /var   - изменяемые файлы (логи, кэш)
# /tmp   - временные файлы
# /usr   - пользовательские программы

# 3. Определение типа файловой системы
df -Th
mount | grep "^/dev"

# 4. Права доступа к корневым каталогам
ls -ld /bin /etc /home /root
```

### Windows

```cmd
:: 1. Просмотр корневой структуры дисков
dir C:\

:: 2. Основные системные директории:
:: C:\Windows       - системные файлы
:: C:\Program Files - программы
:: C:\Users         - пользовательские директории
:: C:\Temp          - временные файлы

:: 3. Определение типа файловой системы
fsutil fsinfo volumeinfo C:

:: 4. Атрибуты системных папок
attrib C:\Windows
dir C:\Windows /Q
```

### Ответ на вопрос

**Ключевые различия в организации корневой файловой системы:**

| Аспект | Linux | Windows |
|---|---|---|
| Корень | Единый корень `/` | Отдельные диски `C:\`, `D:\` |
| Организация | Иерархия по назначению (`/bin`, `/etc`, `/home`, `/var`, `/tmp`, `/usr`) | Иерархия по дискам и папкам (`Windows`, `Program Files`, `Users`) |
| Точки монтирования | Любое устройство монтируется в точку внутри `/` | Каждый диск — отдельный корень со своей буквой |
| Разделитель пути | Прямой слэш `/` | Обратный слэш `\` |
| Регистр | Чувствителен к регистру | Не чувствителен |
| Скрытые файлы | Начинаются с `.` | Имеют атрибут Hidden |

## Навигация и создание структуры каталогов

### Linux

```bash
cd ~
pwd

mkdir -p practical_work/docs/reports
mkdir -p practical_work/docs/drafts
mkdir -p practical_work/code/python
mkdir -p practical_work/code/cpp
mkdir -p practical_work/backups

find practical_work -type d | sort

cd practical_work/code/python
pwd
cd ../../docs/reports
pwd
```

### Windows

```cmd
cd %USERPROFILE%\Desktop
echo %CD%

md practical_work
cd practical_work
md docs\reports
md docs\drafts
md code\python
md code\cpp
md backups

tree /F

cd code\python
echo %CD%
cd ..\..\docs\reports
echo %CD%
```

### Ответ на вопрос

**Различия в синтаксисе команд для создания иерархической структуры каталогов:**

| Действие | Linux | Windows |
|---|---|---|
| Создание каталога | `mkdir dir` | `md dir` / `mkdir dir` |
| Создание вложенных каталогов | `mkdir -p a/b/c` | `md a\b\c` (создаёт все промежуточные) |
| Переход | `cd path` | `cd path` |
| Текущий путь | `pwd` | `echo %CD%` / `cd` |
| Разделитель | `/` | `\` |
| Домашняя директория | `~` или `$HOME` | `%USERPROFILE%` |
| Переход на уровень выше | `cd ..` | `cd ..` |
| Просмотр дерева | `find`, `tree` | `tree` |

В Linux `-p` явно указывает на создание родителей. В Windows `md`/`mkdir` создаёт промежуточные каталоги автоматически.

## Работа с файлами

### Linux

```bash
cd ~/practical_work/docs
echo "Первая строка" > reports/report1.txt
echo "Вторая строка" >> reports/report1.txt
echo "Черновик документа" > drafts/draft1.md

cp reports/report1.txt reports/report_backup.txt
cp -r docs/reports backups/

mv drafts/draft1.md drafts/final_draft.md
rm reports/report_backup.txt

cat reports/report1.txt
head -n 1 reports/report1.txt
tail -n 1 reports/report1.txt

find ~/practical_work -name "*.txt"
find ~/practical_work -type f -mtime -1
```

### Windows

```cmd
cd %USERPROFILE%\Desktop\practical_work\docs
echo Первая строка > reports\report1.txt
echo Вторая строка >> reports\report1.txt
echo Черновик документа > drafts\draft1.md

copy reports\report1.txt reports\report_backup.txt
xcopy docs\reports backups\reports /E /I

ren drafts\draft1.md final_draft.md
del reports\report_backup.txt

type reports\report1.txt
more reports\report1.txt

dir /S /B *.txt
dir /S /B /A:-D | findstr /I "report"
```

### Ответы на вопросы

**Сравнение команд для работы с файлами:**

| Операция | Linux | Windows |
|---|---|---|
| Создать файл | `touch`, `echo >` | `echo >`, `type nul >` |
| Записать с перезаписью | `>` | `>` |
| Дозаписать | `>>` | `>>` |
| Копировать файл | `cp` | `copy` |
| Копировать каталог | `cp -r` | `xcopy /E /I` |
| Переименовать/переместить | `mv` | `ren` (переименовать), `move` (переместить) |
| Удалить файл | `rm` | `del` |
| Удалить каталог | `rm -r`, `rmdir` | `rd`, `rmdir` |
| Просмотр содержимого | `cat`, `head`, `tail` | `type`, `more` |
| Поиск файлов | `find` | `dir /S`, `where` |
| Поиск по содержимому | `grep` | `findstr` |

**Аналогично выполняются:** создание, чтение, копирование файлов, дозапись.

**Существенные различия:**
- В Linux операции копирования и перемещения универсальны (`cp`, `mv`), в Windows разделены (`copy`/`xcopy`, `ren`/`move`).
- В Linux удаление и рекурсивное удаление — одна команда `rm` с флагом, в Windows — разные команды (`del`, `rd`).
- Поиск в Linux (`find`, `grep`) более гибкий и мощный, чем `dir /S` и `findstr`.
- В Linux чувствительность к регистру при поиске файлов, в Windows — нет.

## Права доступа и атрибуты

### Linux

```bash
ls -la ~/practical_work/docs/reports/

chmod 644 reports/report1.txt
chmod 750 reports/
chmod +x code/python/

sudo chown root:root reports/report1.txt
ls -la reports/report1.txt

ln -s ~/practical_work/docs/reports/report1.txt ~/practical_work/backups/link_to_report.txt
ls -la ~/practical_work/backups/
readlink ~/practical_work/backups/link_to_report.txt
```

### Windows

```cmd
attrib docs\reports\report1.txt
icacls docs\reports\report1.txt

attrib +R docs\reports\report1.txt
attrib +H docs\drafts\final_draft.md
attrib -R docs\reports\report1.txt

icacls docs\reports\report1.txt /grant Users:(R)
icacls docs\reports\report1.txt /deny Users:(W)

mklink backups\link_to_report.txt docs\reports\report1.txt
dir backups\
```

### Ответ на вопрос

**Принципиальная разница между моделью прав доступа в Linux (rwx) и Windows (ACL):**

| Аспект | Linux (rwx) | Windows (ACL) |
|---|---|---|
| Модель | Дискреционная, три категории: владелец, группа, остальные | Список управления доступом (Access Control List) |
| Права | r (чтение), w (запись), x (выполнение) | Read, Write, Execute, Delete, Take Ownership, Change Permissions и др. |
| Формат | `rwxr-xr--` (9 бит) | Список ACE (Access Control Entries) с SID и правами |
| Количество субъектов | Владелец, группа, остальные | Любое число пользователей и групп |
| Наследование | Ограничено (setgid, setuid, sticky bit) | Полноценное наследование от родительских объектов |
| Изменение | `chmod`, `chown`, `chgrp` | `icacls`, `cacls`, GUI «Свойства → Безопасность» |
| Гибкость | Простая, но ограниченная | Сложная, но очень гибкая |
| Атрибуты файла | Отдельно от прав (скрытый — `.`, неизменяемый — `chattr +i`) | Атрибуты (R, H, S, A) отдельно от ACL |

**Вывод:** Linux использует простую и компактную модель POSIX, удобную для большинства задач. Windows применяет более мощную, но сложную ACL-модель, позволяющую задавать права для произвольного числа субъектов с наследованием.

## Дисковое пространство и метаданные

### Linux

```bash
df -h
du -sh ~/practical_work/
du -sh ~/practical_work/*

stat ~/practical_work/docs/reports/report1.txt
file ~/practical_work/docs/reports/report1.txt

grep "строка" ~/practical_work/docs/reports/report1.txt
grep -r "документ" ~/practical_work/

tar -czf ~/practical_work_backup.tar.gz ~/practical_work
ls -lh ~/practical_work_backup.tar.gz
tar -tzf ~/practical_work_backup.tar.gz
```

### Windows

```cmd
wmic logicaldisk get size,freespace,caption
dir docs\reports\report1.txt

fsutil file layout docs\reports\report1.txt

findstr "строка" docs\reports\report1.txt
findstr /S /I "документ" practical_work\*

powershell "Compress-Archive -Path practical_work -DestinationPath practical_work_backup.zip"
dir *.zip
```

### Ответ на вопрос

**Инструменты для работы с дисковым пространством и архивацией, родные для каждой системы:**

| Задача | Linux | Windows |
|---|---|---|
| Свободное место | `df`, `du` | `wmic logicaldisk`, `dir`, `Get-PSDrive` |
| Информация о файле | `stat`, `file`, `ls -l` | `dir`, `fsutil file`, `Get-Item` |
| Поиск по содержимому | `grep`, `rg` | `findstr`, `Select-String` |
| Архивация | `tar`, `gzip`, `bzip2`, `xz`, `zip` | `Compress-Archive` (PowerShell), `tar` (Windows 10+) |
| Просмотр архива | `tar -t`, `unzip -l` | `tar -t`, `Expand-Archive`, GUI |

**Вывод:** в Linux архивация традиционно выполняется через `tar` с компрессией (`gzip`/`bzip2`/`xz`). В Windows исторически использовался ZIP, а `Compress-Archive` — современный командлет PowerShell. `fsutil file` — специализированная утилита для работы с метаданными NTFS (экстенты, разреженные файлы, идентификаторы).

## Переменные окружения и пути

### Linux

```bash
echo $PATH
echo $HOME
printenv | grep -E "(USER|HOME|PATH|SHELL)"

export PATH=$PATH:~/practical_work/code/python
echo $PATH

alias ll='ls -la'
alias mydocs='cd ~/practical_work/docs'
alias

which ls
which python3
whereis bash
```

### Windows

```cmd
echo %PATH%
echo %USERPROFILE%
set

set PATH=%PATH%;%USERPROFILE%\Desktop\practical_work\code\cpp
echo %PATH%

doskey ll=dir /w $*
doskey mydocs=cd %USERPROFILE%\Desktop\practical_work\docs

where notepad.exe
where cmd.exe
```

**Различия:**

| Аспект | Linux | Windows (cmd) |
|---|---|---|
| Переменная | `$VAR` | `%VAR%` |
| Разделитель PATH | `:` | `;` |
| Псевдонимы | `alias` | `doskey` (только в cmd), `Set-Alias` (PowerShell) |
| Поиск исполняемых | `which`, `whereis` | `where` |
| Установка переменной | `export VAR=value` | `set VAR=value` |
| Домашняя директория | `$HOME` | `%USERPROFILE%` |

## Создание скриптов для автоматизации

### Linux (bash)

```bash
#!/bin/bash
# backup_script.sh
BACKUP_DIR="$HOME/backups"
SOURCE_DIR="$HOME/practical_work"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
BACKUP_NAME="backup_${TIMESTAMP}.tar.gz"

echo "Создание резервной копии..."
mkdir -p "$BACKUP_DIR"
tar -czf "$BACKUP_DIR/$BACKUP_NAME" "$SOURCE_DIR"

if [ $? -eq 0 ]; then
    echo "Резервная копия создана: $BACKUP_DIR/$BACKUP_NAME"
    echo "Размер: $(du -h "$BACKUP_DIR/$BACKUP_NAME" | cut -f1)"
else
    echo "Ошибка при создании резервной копии!"
    exit 1
fi
```

Запуск:

```bash
chmod +x backup_script.sh
./backup_script.sh
```

### Windows (batch)

```batch
@echo off
REM backup_script.bat
set BACKUP_DIR=%USERPROFILE%\backups
set SOURCE_DIR=%USERPROFILE%\Desktop\practical_work
set TIMESTAMP=%date:~6,4%%date:~3,2%%date:~0,2%_%time:~0,2%%time:~3,2%
set BACKUP_NAME=backup_%TIMESTAMP%.zip

echo Создание резервной копии...
if not exist "%BACKUP_DIR%" mkdir "%BACKUP_DIR%"

powershell "Compress-Archive -Path '%SOURCE_DIR%' -DestinationPath '%BACKUP_DIR%\%BACKUP_NAME%'"

if %errorlevel% equ 0 (
    echo Резервная копия создана: %BACKUP_DIR%\%BACKUP_NAME%
    for /f %%i in ('powershell "(Get-Item '%BACKUP_DIR%\%BACKUP_NAME%').Length/1MB"') do echo Размер: %%i MB
) else (
    echo Ошибка при создании резервной копии!
    exit /b 1
)
```

Запуск:

```cmd
backup_script.bat
```

**Сравнение:**

| Аспект | Linux (bash) | Windows (batch) |
|---|---|---|
| Шебанг | `#!/bin/bash` | Не требуется (`@echo off`) |
| Переменные | `$VAR`, `$(command)` | `%VAR%`, `for /f` |
| Условие | `if [ ... ]; then ... fi` | `if ... ( ... ) else ( ... )` |
| Проверка кода возврата | `$?` | `%errorlevel%` |
| Работа с датой | `date +"%Y%m%d"` | `%date:~6,4%...` (позиционное извлечение) |
| Архивация | `tar -czf` | `Compress-Archive` (через PowerShell) |
| Права на запуск | `chmod +x` | Не требуются |
| Расширение | `.sh` | `.bat`, `.cmd` |

**Вывод:** bash-скрипты более лаконичны и удобны для работы с текстом, датами и архивами. Batch-скрипты ограничены в возможностях и часто вынуждены вызывать PowerShell для сложных операций.

## Итоговый вывод

В ходе практической работы были изучены и сравнены принципы работы с файловой структурой в Windows и Linux.

**Сходства:**

- Иерархическая организация каталогов.
- Наличие базовых операций: создание, копирование, перемещение, удаление, переименование.
- Поддержка прав доступа, атрибутов, символических ссылок, архивов.
- Возможность автоматизации через скрипты.

**Ключевые различия:**

| Аспект | Linux | Windows |
|---|---|---|
| Корень | Единый `/` | Отдельные диски `C:\`, `D:\` |
| Разделитель пути | `/` | `\` |
| Регистр | Чувствителен | Не чувствителен |
| Права | POSIX (rwx, 9 бит) | ACL (списки ACE) |
| Псевдонимы | `alias` | `doskey`, `Set-Alias` |
| Архивация | `tar`, `gzip` | `Compress-Archive`, ZIP |
| Скрипты | bash, мощный | batch, ограниченный |
| Поиск | `find`, `grep` | `dir /S`, `findstr` |
| Ссылки | `ln -s` | `mklink` |

Обе системы предоставляют полный набор инструментов для работы с файлами, но Linux ориентирован на текстовые команды и универсальность, а Windows — на графический интерфейс и обратную совместимость. Понимание обеих моделей важно для кросс-платформенной разработки и администрирования.
