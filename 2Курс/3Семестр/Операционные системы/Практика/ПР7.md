## Теоретическая часть

**Планирование CPU** — механизм, с помощью которого операционная система решает, какой процесс будет выполняться на процессоре в данный момент. Цели планирования: справедливость, высокая производительность, быстрый отклик для интерактивных задач.

**Основные метрики эффективности:**

| Метрика | Формула | Значение |
|---|---|---|
| Время выполнения (Turnaround Time, TAT) | Время завершения – время поступления | Сколько времени прошло от старта до завершения |
| Время ожидания (Waiting Time, WT) | TAT – время выполнения | Сколько процесс ждал в очереди |
| Время отклика (Response Time, RT) | Время первого запуска – время поступления | Насколько быстро система отреагировала |

**Алгоритм FCFS (First-Come, First-Served):** процессы выполняются в порядке поступления. Прост в реализации, но подвержен эффекту convoy effect — один долгий процесс блокирует все остальные.

**Алгоритм Round Robin (RR):** каждому процессу даётся квант времени. Если процесс не завершился, он уходит в конец очереди. Обеспечивает хороший отклик и справедливость, но требует выбора оптимального кванта: слишком большой — превращается в FCFS, слишком маленький — растут накладные расходы на переключение контекста.

**MLFQ (Multilevel Feedback Queue):** несколько очередей с разными приоритетами. Новые процессы попадают в очередь с высоким приоритетом, при использовании всего кванта приоритет понижается. Используется в современных ОС (Windows, Linux).

## Постановка эксперимента

Для сравнения алгоритмов использован симулятор на Python. В качестве исходных данных взяты четыре процесса:

| Процесс | Время поступления | Время выполнения |
|---------|-------------------|------------------|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 2 |
| P4 | 3 | 6 |

Необходимо:
- рассчитать метрики для FCFS;
- рассчитать метрики для Round Robin с квантом = 2;
- сравнить среднее время ожидания.

## Реализация симулятора на Python

```python
from collections import deque
import copy

class Process:
    def __init__(self, pid, arrival, burst):
        self.pid = pid
        self.arrival = arrival
        self.burst = burst
        self.remaining = burst
        self.waiting_time = 0
        self.response_time = None
        self.completion_time = 0

def fcfs(processes):
    processes.sort(key=lambda p: p.arrival)
    current_time = 0
    for p in processes:
        if current_time < p.arrival:
            current_time = p.arrival
        p.response_time = current_time - p.arrival
        p.waiting_time = current_time - p.arrival
        current_time += p.burst
        p.completion_time = current_time
    return processes

def round_robin(processes, quantum):
    processes.sort(key=lambda p: p.arrival)
    queue = deque()
    current_time = 0
    completed = 0
    n = len(processes)
    i = 0
    while i < n and processes[i].arrival <= current_time:
        queue.append(processes[i])
        i += 1
    while completed < n:
        if not queue:
            current_time += 1
            while i < n and processes[i].arrival <= current_time:
                queue.append(processes[i])
                i += 1
            continue
        p = queue.popleft()
        if p.response_time is None:
            p.response_time = current_time - p.arrival
        run_time = min(p.remaining, quantum)
        current_time += run_time
        p.remaining -= run_time
        if p.remaining == 0:
            p.completion_time = current_time
            p.waiting_time = p.completion_time - p.arrival - p.burst
            completed += 1
        else:
            while i < n and processes[i].arrival <= current_time:
                queue.append(processes[i])
                i += 1
            queue.append(p)
    return processes

def print_results(processes, name):
    print(f"\n=== {name} ===")
    total_wt = total_tat = total_rt = 0
    for p in processes:
        tat = p.completion_time - p.arrival
        total_wt += p.waiting_time
        total_tat += tat
        total_rt += p.response_time
        print(f"P{p.pid}: WT={p.waiting_time}, TAT={tat}, RT={p.response_time}, CT={p.completion_time}")
    n = len(processes)
    print(f"Среднее: WT={total_wt/n:.2f}, TAT={total_tat/n:.2f}, RT={total_rt/n:.2f}")

# Исходные данные
procs = [
    Process(1, 0, 8),
    Process(2, 1, 4),
    Process(3, 2, 2),
    Process(4, 3, 6)
]

fcfs_procs = copy.deepcopy(procs)
print_results(fcfs(fcfs_procs), "FCFS")

rr_procs = copy.deepcopy(procs)
print_results(round_robin(rr_procs, quantum=2), "Round Robin (квант=2)")
```

## Результаты FCFS

Порядок выполнения: P1 → P2 → P3 → P4.

| Процесс | WT | TAT | RT | CT |
|---------|----|-----|----|----|
| P1 | 0 | 8 | 0 | 8 |
| P2 | 7 | 11 | 7 | 12 |
| P3 | 10 | 12 | 10 | 14 |
| P4 | 11 | 17 | 11 | 20 |

**Средние значения:**
- WT = (0 + 7 + 10 + 11) / 4 = **7.00**
- TAT = (8 + 11 + 12 + 17) / 4 = **12.00**
- RT = (0 + 7 + 10 + 11) / 4 = **7.00**

## Результаты Round Robin (квант = 2)

Порядок выполнения:
P1(0–2) → P2(2–4) → P3(4–6) → P1(6–8) → P4(8–10) → P2(10–12) → P1(12–14) → P4(14–16) → P1(16–18) → P4(18–20).

| Процесс | WT | TAT | RT | CT |
|---------|----|-----|----|----|
| P1 | 10 | 18 | 0 | 18 |
| P2 | 7 | 11 | 1 | 12 |
| P3 | 2 | 4 | 2 | 6 |
| P4 | 11 | 17 | 5 | 20 |

**Средние значения:**
- WT = (10 + 7 + 2 + 11) / 4 = **7.50**
- TAT = (18 + 11 + 4 + 17) / 4 = **12.50**
- RT = (0 + 1 + 2 + 5) / 4 = **2.00**

## Сравнение алгоритмов

| Метрика | FCFS | Round Robin (q=2) | Изменение |
|---------|------|-------------------|-----------|
| Среднее WT | 7.00 | 7.50 | +0.50 |
| Среднее TAT | 12.00 | 12.50 | +0.50 |
| Среднее RT | 7.00 | 2.00 | –5.00 |

**Интерпретация:**
- Round Robin с квантом 2 значительно улучшает **время отклика** (RT): 2.00 против 7.00. Интерактивные задачи начинают выполняться быстрее.
- Однако **время ожидания** и **время выполнения** немного возрастают (7.50 против 7.00 и 12.50 против 12.00). Это связано с накладными расходами на переключение контекста и с тем, что длинные процессы завершаются позже.
- Уменьшение кванта улучшает отклик, но увеличивает число переключений. Увеличение кванта приближает RR к FCFS.

## Вывод

В ходе практической работы был реализован симулятор планировщика CPU на Python. Сравнение алгоритмов FCFS и Round Robin с квантом 2 на четырёх процессах показало:

- FCFS прост, но даёт высокое время отклика для коротких задач, поступивших после длинных.
- Round Robin обеспечивает справедливое распределение CPU и низкое время отклика, что важно для интерактивных систем.
- Выбор кванта — компромисс между отзывчивостью и накладными расходами.
- Современные ОС используют многоуровневые очереди (MLFQ), автоматически адаптируясь под поведение процессов.

Полученные результаты соответствуют теоретическим сведениям о планировании CPU.
