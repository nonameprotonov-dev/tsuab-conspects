«Синхронизация потоков и процессов»

**Цель:** изучить проблемы синхронизации потоков и процессов, исследовать состояние гонки, критическую секцию, мьютексы, семафоры, мониторы, взаимоблокировки и способы их предотвращения.

**ОС и инструменты:** Windows + WSL2 Ubuntu, GCC, библиотека `pthread`, Python 3.

---

## Теоретическая часть

**Синхронизация** — это координация выполнения нескольких потоков или процессов, чтобы они не мешали друг другу при доступе к общим ресурсам: памяти, файлам, устройствам. Без синхронизации возникают ошибки, зависания и повреждение данных.

Основные проблемы и примитивы синхронизации:

- **Race condition (состояние гонки)** — результат зависит от непредсказуемого порядка выполнения потоков.
- **Критическая секция** — часть кода, работающая с общим ресурсом, которая должна выполняться только одним потоком за раз.
- **Мьютекс** — примитив взаимного исключения, блокирующий вход в критическую секцию.
- **Семафор** — счётчик, ограничивающий число потоков, одновременно работающих с ресурсом.
- **Монитор** — высокоуровневый механизм, объединяющий данные и методы, доступные только одному потоку.
- **Deadlock (взаимоблокировка)** — ситуация, когда потоки ждут друг друга вечно.
- **Предотвращение deadlock** — упорядочение ресурсов, тайм-ауты, алгоритм банкира, обнаружение и восстановление.

## Race Condition (состояние гонки)

**Код `race.c`:**

```c
#include <stdio.h>
#include <pthread.h>

int counter = 0;

void* increment(void* arg) {
    for (int i = 0; i < 100000; i++) {
        counter++;  // НЕАТОМНАЯ операция!
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("Ожидаемо: 200000, Получено: %d\n", counter);
    return 0;
}
```

**Компиляция и запуск:**

```bash
gcc -pthread race.c -o race
./race
```

**Наблюдаемый результат:**

![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260928123205.png]]

Каждый запуск даёт разный результат, не всегда меньше 200000. Это признак состояния гонки.

**Почему `counter++` неатомарна?**  
Операция состоит из трёх шагов:

1. Прочитать значение `counter` из памяти в регистр.
2. Увеличить значение в регистре на 1.
3. Записать новое значение обратно в память.

Между этими шагами может вмешаться другой поток. Если оба потока прочитали одно и то же значение, одно увеличение «теряется».

**Пример гонки:**

| Время | Поток 1 | Поток 2 | Значение `counter` |
|-------|---------|---------|-------------------|
| t1 | читает `counter=5` | — | 5 |
| t2 | — | читает `counter=5` | 5 |
| t3 | увеличивает до 6 | — | 5 |
| t4 | — | увеличивает до 6 | 5 |
| t5 | записывает 6 | — | 6 |
| t6 | — | записывает 6 | 6 |

Результат: 6 вместо 7. Одно увеличение потеряно.

**Вывод:** race condition возникает при одновременном изменении общего ресурса без синхронизации. Такие ошибки трудно воспроизводить и отлаживать; их называют **Heisenbug** — они исчезают при отладке, потому что отладчик замедляет выполнение и меняет порядок потоков.

## Критическая секция

**Критическая секция** — часть кода, которая работает с общим ресурсом и должна выполняться только одним потоком за раз.

Для корректного решения проблемы критической секции необходимо соблюдение четырёх условий:

1. Два процесса не могут одновременно находиться в своих критических областях.
2. Не должно быть предположений о скорости или количестве процессоров.
3. Процессы вне критических областей не могут блокироваться другими процессами.
4. Процессы не должны бесконечно ждать входа в критическую область.

**Взаимное исключение** — способ, при котором доступ к общим данным для чтения и записи получает только один процесс в конкретный момент времени.

## Мьютекс

**Mutex (mutual exclusion)** — примитив, блокирующий вход в критическую секцию. Мьютекс находится в одном из двух состояний: заблокированном или незаблокированном.

**Код `mutex.c`:**

```c
#include <stdio.h>
#include <pthread.h>

int counter = 0;
pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;

void* increment(void* arg) {
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&mutex);
        counter++;  // Критическая секция
        pthread_mutex_unlock(&mutex);
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("Результат: %d\n", counter);  // Всегда 200000!
    return 0;
}
```

**Компиляция и запуск:**

```bash
gcc -pthread mutex.c -o mutex
./mutex
```

**Результат:**
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260928123541.png]]

Теперь только один поток может выполнять `counter++` в любой момент. Результат всегда 200000.

**Как работает мьютекс:**  
Когда потоку нужен доступ к критической области, он вызывает `pthread_mutex_lock`. Если мьютекс свободен, поток входит. Если заблокирован — поток ждёт, пока другой поток не вызовет `pthread_mutex_unlock`. Если ждут несколько потоков, один выбирается произвольно.

## Семафор

**Семафор** — счётчик, ограничивающий число потоков, работающих с ресурсом. Бинарный семафор эквивалентен мьютексу. Общий семафор задаёт максимум, например «максимум 3 потока могут читать файл».

**Код `semaphore.c`:**

```c
#include <stdio.h>
#include <pthread.h>
#include <semaphore.h>
#include <unistd.h>

sem_t sem;

void* worker(void* id) {
    sem_wait(&sem);  // Уменьшить счётчик
    printf("Поток %ld работает\n", (long)id);
    sleep(2);
    printf("Поток %ld завершил\n", (long)id);
    sem_post(&sem);  // Увеличить счётчик
    return NULL;
}

int main() {
    sem_init(&sem, 0, 2);  // начальное значение = 2
    pthread_t t[5];
    for (long i = 0; i < 5; i++) {
        pthread_create(&t[i], NULL, worker, (void*)i);
    }
    for (int i = 0; i < 5; i++) {
        pthread_join(t[i], NULL);
    }
    sem_destroy(&sem);
    return 0;
}
```

**Компиляция и запуск:**

```bash
gcc -pthread semaphore.c -o semaphore
./semaphore
```

## Мониторы

**Монитор** — высокоуровневый механизм синхронизации, в котором данные и методы объединены, и только один поток может выполнять метод монитора. Пример на Python с `threading.Lock`:

**Код `monitor.py`:**

```python
import threading
import time

class Counter:
    def __init__(self):
        self.value = 0
        self.lock = threading.Lock()

    def increment(self):
        with self.lock:  # Монитор-подобное поведение
            temp = self.value
            time.sleep(0.0001)  # имитация задержки
            self.value = temp + 1

counter = Counter()
threads = []

for _ in range(10):
    t = threading.Thread(target=lambda: [counter.increment() for _ in range(100)])
    threads.append(t)
    t.start()

for t in threads:
    t.join()

print("Результат:", counter.value)  # Всегда 1000
```

**Запуск:**

```bash
python3 monitor.py
```

**Результат:**
![[2Курс/3Семестр/Операционные системы/Практика/Attachments/Pasted image 20260928124023.png]]

`threading.Lock` реализует монитор-подобную защиту: только один поток выполняет `increment` в любой момент.

## Deadlock (взаимоблокировка)

**Deadlock** — ситуация, когда два или более потока ждут друг друга вечно.

**Условия возникновения (по Coffman):**

1. Взаимное исключение — ресурс не может быть разделён.
2. Удержание и ожидание — поток держит ресурс и ждёт другой.
3. Отсутствие принудительного освобождения — нельзя отобрать ресурс.
4. Циклическое ожидание — A ждёт B, B ждёт A.

**Код `deadlock.c`:**

```c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

pthread_mutex_t m1 = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t m2 = PTHREAD_MUTEX_INITIALIZER;

void* thread1(void* arg) {
    pthread_mutex_lock(&m1);
    printf("T1: захватил m1\n");
    sleep(1);
    pthread_mutex_lock(&m2);  // Ждёт m2
    printf("T1: захватил m2\n");
    pthread_mutex_unlock(&m2);
    pthread_mutex_unlock(&m1);
    return NULL;
}

void* thread2(void* arg) {
    pthread_mutex_lock(&m2);
    printf("T2: захватил m2\n");
    sleep(1);
    pthread_mutex_lock(&m1);  // Ждёт m1
    printf("T2: захватил m1\n");
    pthread_mutex_unlock(&m1);
    pthread_mutex_unlock(&m2);
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, thread1, NULL);
    pthread_create(&t2, NULL, thread2, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}
```

**Компиляция и запуск:**

```bash
gcc -pthread deadlock.c -o deadlock
./deadlock
```

## Предотвращение deadlock

**Стратегии предотвращения:**

| Метод | Как работает |
|-------|--------------|
| Упорядочение ресурсов | Всегда захватывать мьютексы в одном порядке (сначала `m1`, потом `m2`) |
| Тайм-ауты | Использовать `pthread_mutex_timedlock()` |
| Избежание | Алгоритм банкира (Banker's algorithm) для ОС |
| Обнаружение и восстановление | Периодически проверять граф ожидания |

**Исправленный код (упорядочение):**

```c
// В обоих потоках:
pthread_mutex_lock(&m1);
pthread_mutex_lock(&m2);
// ...
pthread_mutex_unlock(&m2);
pthread_mutex_unlock(&m1);
```

Теперь deadlock невозможен, так как оба потока захватывают ресурсы в одном порядке.

## Сравнение примитивов синхронизации

| Примитив | Назначение | Особенности |
|----------|------------|-------------|
| Мьютекс | Взаимное исключение | Один поток в критической секции |
| Семафор | Ограничение числа потоков | Счётчик, может быть бинарным |
| Монитор | Высокоуровневая синхронизация | Данные + методы, один поток |
| Критическая секция | Защита общего ресурса | Требует примитива синхронизации |

## Ответы на контрольные вопросы

**Что такое синхронизация?**  
Координация выполнения потоков или процессов для безопасного доступа к общим ресурсам.

**Почему `counter++` неатомарна?**  
Операция состоит из чтения, увеличения и записи. Между этими шагами может вмешаться другой поток.

**Что такое критическая секция?**  
Часть кода, работающая с общим ресурсом, которая должна выполняться только одним потоком за раз.

**Какие четыре условия необходимы для решения проблемы критической секции?**  
1. Взаимное исключение.  
2. Независимость от скорости и числа процессоров.  
3. Процессы вне критической секции не блокируются.  
4. Нет бесконечного ожидания.

**Что такое мьютекс?**  
Примитив взаимного исключения, блокирующий вход в критическую секцию.

**Чем семафор отличается от мьютекса?**  
Мьютекс пропускает только один поток. Семафор может пропускать несколько потоков, ограничивая их число счётчиком.

**Что такое монитор?**  
Высокоуровневый механизм, объединяющий данные и методы, доступные только одному потоку.

**Что такое deadlock?**  
Ситуация, когда потоки ждут друг друга вечно.

**Какие условия возникновения deadlock по Coffman?**  
Взаимное исключение, удержание и ожидание, отсутствие принудительного освобождения, циклическое ожидание.

**Как предотвратить deadlock?**  
Упорядочить захват ресурсов, использовать тайм-ауты, применять алгоритм банкира, обнаруживать и восстанавливать.
